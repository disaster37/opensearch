# Plan: Fix zero-value sentinels and remove CreateParams duplicate

## Context

After implementing typed param structs, a local code review identified three issues:

1. **Zero-value sentinel bug**: `IfSeqNo`, `IfPrimaryTerm`, `Size`, and `From` use `!= 0` as the "not set" sentinel, but `0` is a legitimate OpenSearch value (e.g., `if_seq_no=0` for the first document, `size=0` for aggregations-only searches).
2. **Duplicate struct**: `CreateParams` is a byte-for-byte duplicate of `IndexParams`.

## Changes

### 1. `api/options.go` — Use pointer fields for zero-ambiguous values

Change these fields from value types to pointer types across all affected param structs:

Update the corresponding `ToMap()` methods to check `p.Field != nil` instead of `p.Field != 0`, and dereference the pointer: `strconv.FormatInt(*p.IfSeqNo, 10)`.

Update `searchParamsFromURLParams()` to allocate pointers when parsing:
```go
if v, ok := urlParams["size"]; ok {
    n, _ := strconv.Atoi(v)
    p.Size = &n
}
```

### 2. `api/options.go` — Remove CreateParams, use IndexParams

Delete the `CreateParams` struct and its `ToMap()` method entirely. Change `CreateRequest.Params` from `*CreateParams` to `*IndexParams`.
